# Data and artifact policy

## Local-only resources

The following repository-root directories are local working locations and are ignored by Git:

| Path | Intended local content |
| --- | --- |
| `base_models/` | Base model files obtained under their upstream terms |
| `lora_weights/` | Locally trained or obtained adapter weights |
| `checkpoints/` | Training and routing checkpoints |
| `data/` | Locally prepared datasets and intermediate data |
| `inputs/` | User-provided text, image, and diagram inputs |
| `outputs/` | Generated instructions, recognition results, metrics, plots, reports, and caches |
| `logs/` | Local runtime logs |

These directories are not distributed with the repository. Create or populate them locally as required by the selected workflow.

## Inputs

The main inference entrypoint uses `inputs/` by default. Organize local files as:

```text
inputs/
  text/   # .txt requirement files
  image/  # local .jpg or .png image requirements
  uml/    # local .jpg or .png diagram requirements
```

If the directory is absent, the main entrypoint creates this structure and asks the user to add files. Local inputs may contain confidential or copyrighted material; review them before use and do not commit them.

## Outputs and caches

Generated outputs and caches are local artifacts. Code paths create their target directories when needed. Cache-backed evaluation modes require caches generated by the corresponding local inference or experiment workflow; they are not available in a fresh clone.

Do not edit cached predictions or metrics to make a run appear successful. If a result is selected for public release, document the generating commit, command, model and data identifiers, metric configuration, and license or confidentiality review.
